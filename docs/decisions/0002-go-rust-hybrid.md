# [ADR-0002] Go + Rust ハイブリッド構成

| 項目 | 内容 |
|---|---|
| ステータス | 承認 |
| 決定日 | 2026-06-27 |
| 関連ADR | ADR-0001, ADR-0004 |

## コンテキスト

Merlon は API/CRUD 層と、ルール評価エンジン（CDD スコアリング・TM 評価・スクリーニング・バックテスト）という性質の異なる 2 種類の処理を持つ。両者の実装言語を選定する必要がある。

API/CRUD 層は開発速度と保守性が重要である。一方、ルール評価エンジンは計算負荷が高く、特にバックテストではヒストリカルデータに対する大量の評価を行う。

## 決定

API を Go、エンジンを Rust で実装し、両者を gRPC（Protocol Buffers）で通信させる。

## 根拠

- **Go** は CRUD/API 開発の生産性が高く、エコシステムが充実している
- **Rust** はルール評価・バックテストの計算負荷に適する。GC による停止がなく、メモリ安全性をコンパイル時に保証する
- Proto 定義を契約とすることで、両言語を疎結合に保てる

## 棄却した代替案

- **全 Go** — エンジン部分で GC の影響を受け、大量評価時のレイテンシが不安定になりうる
- **全 Rust** — API/CRUD 開発の生産性が低下し、小規模体制では開発速度を確保しにくい

## 影響

- gRPC のレイテンシを M1.8 で実測し、目標（P95 < 100ms）に達しない場合はフォールバック（同一プロセス化等）を検討する
- 2 つのツールチェーン（Go / Rust）を CI・開発環境で維持する必要がある

## 注記

Proto 定義が Go/Rust 間の契約である。この契約を安定に保つ限り、エンジンの実装言語を将来変更しても API 側には影響しない設計とする。
