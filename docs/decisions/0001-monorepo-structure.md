# [ADR-0001] モノレポ構成の採用

| 項目 | 内容 |
|---|---|
| ステータス | 承認 |
| 決定日 | 2026-06-27 |
| 関連ADR | ADR-0002 |

## コンテキスト

Merlon は Go API、Rust Engine、Protocol Buffers 定義という複数のコンポーネントから構成される。これらをどのリポジトリ構成で管理するかを決める必要がある。

主要な制約は、Proto 定義が Go と Rust の間の契約であり、Proto を変更すると両言語のコードを同時に更新する必要がある点である。また開発体制は 1〜2 名と小規模であり、リポジトリ間のバージョン同期にコストをかけられない。

## 決定

単一リポジトリ（モノレポ）で Go API、Rust Engine、Proto 定義、UI、デプロイ設定をまとめて管理する。

## 根拠

- Proto 変更時に Go 側・Rust 側の更新を 1 コミットで完結でき、契約と実装の整合が常に取れる
- 小規模開発体制において、リポジトリ間のバージョン同期コストを排除できる
- CI/CD・ドキュメント・デプロイ設定を一元管理できる

## 棄却した代替案

- **3 リポジトリ分離（api / engine / proto）** — Proto 変更が複数 PR・複数リポジトリにまたがり、同期コストが大きい。1〜2 名体制には過剰
- **Git Submodule** — clone 時の障壁、サブモジュールのポインタ管理が煩雑。変更の原子性が確保できない

## 影響

- CI/CD では `paths` フィルタを設計し、変更されたコンポーネントのみをビルド・テストする必要がある
- リポジトリが大きくなるため、ディレクトリ構成と所有範囲を明確に保つ
