# [ADR-0004] スコア駆動アーキテクチャ

| 項目 | 内容 |
|---|---|
| ステータス | 承認 |
| 決定日 | 2026-06-27 |
| 関連ADR | ADR-0002 |

## コンテキスト

Merlon は CDD（顧客デューデリジェンス）スコアリングと TM（取引モニタリング）を持つ。これらの関係をどう設計するかを決める必要がある。

FSA のリスクベース・アプローチは、顧客のリスク格付けに基づいた管理を要求する。高リスク顧客にはより厳格な管理を、低リスク顧客には緩和した管理を適用すべきである。

## 決定

CDD スコアをシステム全体の中心軸とする。TM の閾値、ケースの優先度、スクリーニングの頻度は、いずれも CDD スコア（リスクティア）から導出される。

## 根拠

- FSA のリスクベース・アプローチは顧客リスク格付けに基づく管理を要求しており、CDD スコアを中心に据えることでこれに整合する
- 高リスク顧客には TM の閾値を厳格化（より検知しやすく）し、低リスク顧客には緩和することで、リソースをリスクに応じて配分できる
- 単一のリスク指標（CDD スコア）を軸とすることで、システム全体の挙動が一貫し、説明可能になる（Auditability First とも整合）

## 棄却した代替案

- **CDD と TM を独立に運用** — リスク格付けと取引監視が連動せず、リスクベース・アプローチの要求を満たしにくい

## 影響

- CDD スコアリングエンジンを最初に実装する（M1.3）
- TM エンジン（M2.1）は CDD スコアを入力として受け取る設計とする
- スコアの算出根拠とバージョンを保持し、過去の判断を再現可能にする（[data-retention.md](../compliance/data-retention.md) 参照）
