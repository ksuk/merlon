## コンテキスト

Merlon はソースコードの透明性と、持続可能なビジネスモデルの両立を求められる。AML/CFT ドメインでは、判断ロジックがブラックボックスでないこと（透明性）が導入企業の信頼に直結する。一方、ソースコードを無制限に商用利用可能にすると、ビジネスモデルが毀損する。

ソースコード公開方針と、コンテンツ（ルールプリセット）販売モデルの両立を実現するライセンスを選定する必要がある。

## 決定

ソースコードに **BSL 1.1（Business Source License 1.1、source-available）** を採用する。Change Date 経過後は Apache-2.0 へ自動的にアップグレードされる。

## 根拠

- ソースコードの透明性を確保し、AML ドメインでの信頼性を担保する
- 無制限の商用利用を制限することで、ビジネスモデルの毀損を防ぐ
- Change Date 後の Apache-2.0 移行により、長期的なオープン性も担保する
- コンテンツ（ルールプリセット）は独立した商用ライセンスで提供し、ソフトウェア本体と分離する

## 棄却した代替案

- **Apache-2.0 / MIT** — 商用利用の保護がなく、ビジネスモデルを維持できない
- **プロプライエタリ** — 透明性がなく、コミュニティ形成が困難
- **AGPL** — 導入企業に対しソース公開義務が及び、企業導入の障壁となる

## 影響

- BSL 1.1 は OSI 承認ライセンスではないため、「open source」とは表記しない。**「source-available」** と表記する
- ライセンス条項（追加利用許諾範囲、Change Date）を明確に定義・公開する必要がある
- Additional Use Grant により導入組織自身（および関連会社）の本番利用は許諾される。制限されるのは、第三者に対して Licensed Work の機能をホステッド／マネージド／組込サービスとして商用提供すること（SaaS ラッパー再販）のみ
